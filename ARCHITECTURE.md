# MauriStocks architecture

## Shared masthead migration (draft Issue #31)

The shared ambient shapes use a negative stacking level by design. MauriStocks must keep its document root and `html` canvas transparent; painting the `--bg` color at `:root` or `html,body` obscures them. The `body` retains its normal `--bg` background and all stock data palette variables are unchanged.

The Homepage-owned nested `shared/ui/banner` module renders the stock page's common masthead with semantic app title, executable version/build, native same-tab Homepage return, and existing verified identity hook. Its stylesheet and original two blurred Homepage ambient shapes are embedded in the no-store dashboard page at build time; its viewport-relative widths and responsive gutters are never copied into stock-specific selectors. The masthead is outside the centered `.stocks-content` region. The existing 12-hour Homepage bearer verification and browser-only fallback update `suite-auth-status`; the banner does not authorize users or synchronize accounts. Tanner's identical JPEG is embedded in the binary and served locally. No external runtime Homepage CSS or image request is introduced. Stock table, heatmap, dialogs and refresh remain application-owned.

MauriStocks keeps its HTTP server, Yahoo Finance request/cache and quote transformation logic, and an embedded HTML/CSS/JavaScript dashboard in [main.go](main.go). [go.mod](go.mod) adds the pinned `github.com/richard-mauri/homepage/shared/ui` module to the standard library. This document describes current ownership, not a completed package refactor.

## Canonical suite buttons

Homepage's `shared/ui` Go module embeds the suite's authoritative `buttons.css`. MauriStocks includes those bytes in its existing inline stylesheet at page-template rendering time; the module is a build-time dependency, not a browser-time Homepage fetch, and no Content Security Policy exception is introduced. Ordinary controls (Refresh quotes, watchlist actions, dialog actions, and the dynamically created Reset columns button) **must** use `button.ui-button`. Local CSS may provide layout and map `--text`/`--line` to the dashboard's `--ink`/`--border` palette, but must not duplicate or override shared ordinary-button appearance, hover, disabled, or focus states. Table sorting buttons (`.sort-button`) and persistent watchlist stars (`.symbol-flag`) have distinct semantic presentations and deliberately remain specialized. Review this contract when adding any button.

Confirmation dialogs focus the dialog container on opening instead of programmatically focusing OK, which previously showed Homepage's keyboard-focus ring before any user interaction. The container has no visual outline; Tab still enters the standard buttons and Enter confirms from the container. The text-entry dialog intentionally focuses its input. The shared button focus styling remains unchanged.

## Account settings comparison (Issue #33)

When Homepage verifies a named account, `reconcileAccountOnSignIn()` compares the schema-1 per-user record with the existing browser localStorage snapshot. A mismatch opens a read-only, scrollable collection of compact cards showing only different keys, with labeled browser/account values and per-list symbol absences/additions where parseable. On narrow screens each pair stacks vertically, with no three-column horizontal scrolling. The legacy selected-symbol mirror is suppressed only when it exactly represents the same active named-watchlist discrepancy. The dialog uses `textContent` for every value to avoid interpreting saved names or values as markup. A missing key is shown explicitly; invalid legacy serialized data is shown as-is rather than discarded. The two actions still retain the exact prior semantics: keep browser state without an account write, or replace all browser keys with the saved account snapshot and reload, with rollback on localStorage failure. Explicit watchlist commits first persist locally and start an immediate (non-debounced) Homepage save when authenticated, with pending/confirmed/declined/failed synchronization feedback; a local commit does not imply server success. Other preference autosaves retain their 400 ms debounce. No API, account revision, schema, authentication or server data changes; queued saves and server overwrite/revision guards remain separate.

## Responsibilities

The server handles network retrieval, caching, validation, quote/session calculation and API routes. The embedded browser client handles watchlists, column show/hide preferences, sort selection, flags, refresh controls, symbol research links and DOM rendering. Browser state is localStorage, not a server-side database. The quote table sizes visible columns from content (small horizontal padding); range graphs have a minimum usable width and long names may be ellipsized. No draggable/manual width state is used. Regular-session conditions still suppress the extended-price column.

The browser must not receive API secrets. `FINNHUB_API_KEY` is a server-side optional setting. Yahoo Finance interfaces used here are unofficial and subject to upstream availability. Retain loopback binding by default.

## Boundaries and changes

Keep UI-only adjustments inside the embedded markup/script without changing quote data semantics or endpoints. Changes to retrieval, caching or pricing require independent review and regression coverage. A future package split should place UI, HTTP transport, provider integration and quote/domain calculation behind clear interfaces, rather than moving code merely to create directories. See [DEVELOPMENT.md](DEVELOPMENT.md) for verification.
## Return to Homepage navigation
MauriStocks's browser UI exposes a visible native anchor `<a href="https://home.themauris.org/">← Back to Homepage</a>` with no `target` and no JavaScript history manipulation. It navigates in the current tab and can be used regardless of account sign-in. The link adds no new server endpoints, exposes no credentials, and does not modify app-local state. This navigation is part of the merged five-service Homepage suite; the card links navigate in the same tab.

The suite-wide return button uses the same `.suite-home-link` presentation in all four apps: 38px minimum height, 8px/12px padding, 10px radius, muted border at rest, accent border and darker fill on hover, and a visible keyboard focus outline. Place one link at the upper-left above the primary content/heading.

The shared suite navigation style is a quiet 12px text link below each page's primary heading, with subtle hover background and underline and keyboard focus outline. There is no app-specific Renew button.

## Twelve-hour Homepage sign-in handoff
MauriStocks uses a transfer bearer linked to Homepage's single twelve-hour session. The account header displays identity only, without a countdown; its internal expiry handling remains unchanged. The bearer cannot remain valid after Homepage sign-out/session expiry. No separate app token renewal UI exists. On a Homepage `#suite_mode=local` launch, MauriStocks clears its cached bearer and enters browser-only mode without deleting watchlists or browser preferences. A valid `#suite_token=...` launch replaces it; an ordinary refresh can reuse a previously delivered bearer subject to server validation. On direct HTTPS visits without a bearer, MauriStocks navigates to the fixed Homepage `/launch/stocks` bridge: Homepage's own same-origin code uses its retained session ID or host-only cookie to POST a new parent-bound handoff, then returns `#suite_token=...` or `#suite_mode=local`. Explicit local mode suppresses further recovery only on that visit, preventing loops; later visits check Homepage again. Cached expiry triggers bounded profile revalidation before discarding a bearer, since the Homepage parent may already have been renewed. No new local login, personal token retention, or app renewal operation is introduced. These are coordinated with Homepage Issue #24. The matching Homepage PR #12 and NewsGo PR #53 are merged; the owner accepted coordinated Safari behavior.

## Watchlist heatmap (Issue #13, merged)

The dashboard now has Table and Heatmap views over the same in-memory `quotes` array and existing `refreshQuotes()` timer. A successful quote refresh repaints the heatmap; switching views does not start a second quote poller. The heatmap uses regular-market price relative to previous close for color, rather than reusing the table's session-dependent change field. Area comes from independent company capitalization metadata, not share price. Tiles reuse `researchURL()` and the browser's selected research destination.

`/api/market-caps` uses Finnhub Company Profile 2 with a server-only `FINNHUB_API_KEY`. The response includes USD capitalization, source and retrieval timestamp where available. Requests are serialized and rate-spaced independently of quote retrieval. Successful metadata is cached for 24 hours; missing-cap metadata for one hour. This is an additive endpoint, not a change in the existing `/api/quotes` contract. Unavailable securities are displayed separately, never given invented market-cap weights. Metadata failures must not interrupt quote updates. Browser-only view preference uses `mauristocks_view_v1`; existing Homepage account settings keys and their per-user isolation are unchanged.

The first version uses a small alternating-axis area-preserving binary treemap with no JavaScript dependency. No major-index universe, sector map, historical change selector, or heatmap export is included. Mac/Safari and provider acceptance remain outstanding.

## Market Top 30 selections (PR #15, merged)

`market_indices.go` implements `/api/market-top?market=sp500|nasdaq100|dow30`, validating upstream CSV membership and market capitalization snapshots, ranking eligible index constituents, returning 30 symbols plus available per-symbol USD caps, and keeping a shared six-hour in-memory snapshot for all three indexes. Sources: zyhe16 daily Nasdaq screener snapshots/S&P membership, yfiua monthly constituent lists for NASDAQ-100 and Dow. These are not real-time, official index weights. Dow members are retained even when an individual cap is unavailable. The browser stores a separate `mauristocks_market_v1` selection, makes watchlist edits unavailable while viewing an index, seeds the existing per-symbol browser cap cache from each server response, and retains the exact same `/api/quotes` and refresh cycle. Account credentials and per-user watchlist storage are unchanged. Provider failures are visible to the user and are not replaced with guessed constituents.

## Adjustable heatmap capitalization exponent

Heatmap's Tile weighting slider controls exponent `p` in geometric weight `market_cap ** p`, 0.50–1.00 in 0.05 increments (default 0.65). The binary treemap partitions on the exponentiated weight; actual USD capitalization remains in `cap` for tooltips and ranking. Including the exponent in `layoutKey` forces a treemap relayout when the control changes, without new quote or metadata fetches. The footer accurately describes adjusted versus exact area. Browser localStorage key `mauristocks_heat_weight_v1` is included in the existing per-user Homepage settings snapshot, alongside `mauristocks_market_v1` and `mauristocks_view_v1`. The three UI change handlers invoke the shared debounced `queueSuiteSave()` path when authenticated; browser-only sessions persist locally without a server request. No API change is required: Homepage's per-user JSON store accepts the existing schema-1 settings record and enforces bearer identity, revision conflicts and overwrite approval. Provider metadata caches remain browser-only, not part of account settings.

## Stable heatmap tile DOM across refreshes

Treemap relayout reconciles existing anchors by symbol rather than clearing all tiles. On a change to exponent or capitalization, positions are updated on existing nodes; only newly added symbols create nodes and departed symbols are removed. This avoids empty-container flashes, preserves existing colors and research links during ongoing quote refresh, and retains keyboard focus for unchanged symbols. Layout updates still use the same geometric weighted partition and tooltip capitalization values.

## Consolidated browser autosave and heatmap preferences (PR #18)

Historical PR #18 explored browser autosave after inactivity, blur/change, watchlist switches and refresh. This behavior is superseded by the current explicit-save implementation in Issue #33. Save Changes and Load from account controls are removed. Save As New still creates named lists; Default, dynamic and index lists remain protected. Per-account sign-in reconciliation reads Homepage's saved record once per account identity, prompts before replacing divergent browser settings, and retains existing account-overwrite and optimistic revision guards. When signed in, all user-editable persisted preferences (including Market, View and Tile weighting) go through the shared debounced account save. The existing schema-1 JSON and per-user server authorization remain unchanged; market-cap/quote metadata caches remain local. The weighting slider is independent of the original palette and leaves quote data and exact capitalization tooltips unchanged.

## Unified Market selection and explicit symbol edits (proposed)

The Market menu now dynamically includes Default, named watchlists, Most Active, and the three index choices. Its personal-list option values have a `list:` prefix to avoid colliding with index keys; the existing `mauristocks_market_v1` (`watchlist` or index) and active-watchlist localStorage keys remain compatible. The separate Watchlist selector is removed. Saved personal-list contents are compared against normalized text-field symbols. Save Changes (named lists only), Save As New, and Restore Watchlist are enabled only for applicable pending changes; switches require confirmation before discarding edits. Quote refresh reads pending text without writing it to the saved watchlist or its legacy symbol key. Explicit commits now stage the named-list changes and perform a single user-initiated browser storage save followed by a Homepage PUT; other preferences are also staged and never synchronized automatically (Issue #33). Default, dynamic, and index definitions remain protected. The earlier PR #18 autosave behavior above is historical context superseded by this proposed change.

## Suite activity reporter (Issue #19, merged; verified identity in Issue #22)

An optional `ActivityReporter` lives in `activity.go` and is enabled only with `STOCKS_ACTIVITY_URL` and `HOMEPAGE_ACTIVITY_KEY_STOCKS`. The existing single-file application in `main.go` wraps its price, market, Most Active and company lookup routes to count in-flight requests independently from browser presence. It adds `/api/activity/ping` plus the embedded `/activity.js` only while the reporter is enabled, and injects a single defer-loaded heartbeat script into the page template without affecting its existing inline application code. The script uses a 128-bit ephemeral per-tab identifier, stored only in tab sessionStorage, and submits visibility and interaction hints to the local same-origin endpoint. The server bounds, rate-limits and expires tab IDs in memory. Every minute it sends **aggregated** counts through a short-timeout, no-redirect POST to Homepage's `/api/admin/activity/ingest`, authenticated by an environment-only key for service `stocks`. The payload contains no symbols, prices, accounts or per-browser IDs. Missing or stale Homepage observations must show unknown. Issue #22 added server-side Homepage profile verification: verified parent-session aliases deduplicate tabs and distinguish named/guest signed-in activity; invalid bearers return 401 and verification outages 503. No restart decision or controls are added.

## Account comparison and synchronization feedback (Issue #33 follow-up)

`mauristocks_columns_v1` stores `{hidden:[columnId,...]}`, not per-column booleans. The comparison reads and normalizes known hidden IDs and shows only columns whose visibility differs, with a human-readable label and shown/hidden state on each side. Unknown legacy column IDs and hidden Symbol entries are ignored for display; malformed records remain plain text. Stored settings and reconciliation/overwrite behavior are unchanged. The account-sync status reports pending unsaved edits and persists after the explicitly initiated Homepage PUT succeeds/fails. A successful profile revalidation must not clear the last status; keeping browser settings instead explicitly reports that the account remains unchanged. Account synchronization is explicit for all preferences and editable watchlist symbols; Save Changes is enabled by any staged preference, symbol edit, or failed-account-save retry. The separate Homepage CORS fix (Homepage draft PR #59) must be deployed for cross-origin PUT success. `scripts/test-account-diff.cjs` exercises the visible-columns comparison and status regression, and CI runs it with Node.

## Compact account review (Issue #33 Safari acceptance follow-up)

The account review dialog uses a bounded flex-column layout: explanatory title/message and action buttons stay fixed, while `#suite-dialog-diff` alone scrolls inside the viewport. A closed native dialog remains hidden. Symbols in the same named watchlist are compared as set deltas, rendered once with counts under **Added in this browser** and **Removed from this browser**, rather than duplicated two-column inventories. When the selected watchlist differs across browser/account, the legacy `mauri_stock_symbols` copy is suppressed only if each side's symbols exactly match its own selected named list; the selected watchlist comparison still appears. This prevents a false 'all symbols added/removed' report when Default and Candidates are simply different selections. Malformed records retain safe text fallback; account snapshots and server permissions remain unchanged.

## Named-watchlist comparison identity (Issue #33 correction)

Only `mauri_stock_watchlists_v1` contains editable personal watchlist definitions. The embedded Default list uses the fixed `defaults` string and is excluded from saved personal-list parsing; the dynamic Most Active list is likewise excluded from content comparison. `mauri_stock_active_watchlist` identifies the selected list, and `mauri_stock_symbols` is a legacy selected-list mirror, **not** a separate list or an aggregate of all symbols. The comparison skips the mirror unconditionally, compares only like-named personal watchlists in the browser and account maps, and uses `Present (N symbols)`/`Not present` for missing lists (no deletion history is available). Symbol additions/removals and order differences appear within the same named list's card using the shared This browser/Saved account pair, as do Visible Columns. Unchanged lists and irrelevant JSON object property order are omitted. If only mirrored/formatting bytes differ, sign-in reconciliation avoids showing an empty review dialog. This changes only how existing schema-1 snapshots are compared; no persistent data or Homepage authorization changes.

## Shared browser/account comparison headings (Issue #33 draft)

The in-page `suiteAsk` review now mounts `#suite-dialog-column-headings` between the explanation and `#suite-dialog-diff`. It contains a single **This browser / Saved account** column-label pair, shares the two equal-width grid tracks with `.suite-diff-pair`, and is visible only for a differences review. The header is a flex-shrink-proof sibling of the scrollable differences region and stays above it while the cards scroll; the existing decision-button footer remains outside the scroller. Desktop hides redundant per-cell labels, whereas the narrow-screen `max-width:550px` breakpoint hides the shared row, stacks values, and restores each side label. Header visibility is reset for non-diff confirmation and text-entry dialogs. Values remain text-only and the existing compare, save, auth and restore rules are unchanged.

## Unified explicit save semantics (Issue #33)

The UI maintains `pendingSettings` in memory, representing changed schema-1 preference keys without mutating `localStorage` during interaction. The `stageSetting` function updates UI dirty state and feedback; every user-driven preference handler (refresh interval, columns, market/selected list, sort, research destination, flags, Table/Heatmap and weight slider) routes through it. Initial page setup must not stage settings; initial legacy watchlist migration is pending, not silently persisted. Cached market-cap metadata remains independent of account settings and may continue local cache writes. Quote fetching never commits pending user edits.

`commitSettings` is invoked only by Save Changes or the existing explicit Save As New / confirmed Delete List actions. It validates editable named-list symbols, updates the pending record, writes all changed keys transactionally (with rollback on storage failure), and—only when signed in—calls `saveWatchlistToAccount` to PUT the complete committed snapshot. A failed server save or declined overwrite leaves the committed browser copy intact and `accountSyncNeeded` enables a later manual retry; no debounce timer or automatic account retry remains. A successful PUT updates `suiteRevision` and clears retry state. The browser prompts before leaving while staged settings remain; the local state is never uploaded merely because a preference changed. Sign-in comparison preserves full-snapshot restore/rollback and per-user authorization. This is a change of client commit timing, not account schema, bearer identity, endpoint, or server permissions.
